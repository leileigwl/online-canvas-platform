# MVP 原型说明

> 首版按单用户编辑设计，不包含多人同时编辑、项目成员、在线光标和实时同步。

## 视觉方向

近黑色无限工作区、低对比灰色点阵、柔白文字和简洁工具。点阵只是空间线索，不形成固定画板边缘。沿用用户喜欢的黑点点风格，不加入提示词库、音乐或视频。

## 页面和动作

| 页面 | 关键内容 | 主要动作 |
|---|---|---|
| 登录/注册 | 唯一用户名和密码 | 注册、登录、登出；不收集邮箱 |
| 项目首页 | 我的项目、最近访问、新建 | 创建、打开、重命名、删除 |
| 无限画布 | 顶栏/工具栏/点阵/素材和图层/Agent 面板 | 添加/编辑对象、多选、撤销、缩放 |
| 图片素材库 | 私有素材、搜索和多选 | 添加到个人画布或附加给 Agent |
| Agent 团队设置 | Coordinator、专业角色和模型映射 | 测试连接、分配模型、设限额 |
| Agent 运行面板 | 计划、任务树、审批、结果预览 | 确认/拒绝、取消、重试、应用/撤销 |
| 账户设置 | 用户名和账户安全 | 改密码、注销；忘记密码恢复暂不支持 |

## Agent 为什么在画布里

Agent 是把用户说的创作目标转成画布可执行操作的助手。例如用户选中商品图并提出海报目标，Planner 形成版式，Canvas Editor 提出移动/缩放等操作，Reviewer 检查后展示预览。用户接受后才应用，可撤销。

这样设计是为了减少用户逐个摆放素材的重复操作，同时让每一步有明确职责和边界：Coordinator 负责任务分配，专业 Agent 各做计划、画布编辑或检查，API 负责权限和 revision 校验。Agent 不能直接写数据库或执行任意代码；MVP 也不调用尚未提供的生图/改图 API。

## 多 Agent 状态

- 规划：Coordinator 摘要目标、Agent 角色和任务依赖。
- 并行执行：专业 Agent 分别显示状态和结果摘要。
- 等待审批：显示目标、可能费用/副作用及确认/拒绝按钮。
- 部分失败：成功产物与失败任务分组，重试不重复已完成副作用。
- 待审阅：列出画布对象差异；用户接受后写入个人画布。
- 凭证隐私：显示模型已配置，不显示 API Key。

## 保存和错误状态

- 保存中、已保存、保存失败、版本冲突均有明确状态。
- 保存失败时保留可恢复草稿；旧 revision 写入时提供保留草稿或载入服务端版本。
- Agent 模型未配置、任务排队/超时、取消中和部分失败都提供下一步操作；生图/改图失败状态待接口接入后设计。
- 素材上传中、格式错误、超限和访问失败有对应提示。

## 原型走查顺序

先走查用户名注册/登录和项目首页；再走查单人画布、素材多选和保存冲突；最后走查 Agent 配置、计划、并行任务、审批和结果审阅。补齐空、载入、错误和窄屏状态。
