# PRODUCT.md：产品边界

> 状态：单用户编辑的 MVP 产品基线，2026-10-29。产品设计和技术选型已整理；下一步完善原型并调试 UI。

## 一句话

一个在线黑色点阵无限画布，供个人创作者整理图片、构思视觉方案，并让多 Agent 协助完成创作。

## MVP 包含

- 唯一用户名和密码注册/登录、登录后改密码和账户注销；不收集邮箱，不提供邮箱找回或管理员后台。
- 用户自己的项目、画布、图片素材与 Agent 配置，所有数据按用户所有权隔离。
- 无限画布基础编辑：平移、缩放、选择、拖动，添加图片/文字/基础形状，撤销/重做、自动保存和 revision 冲突保护。
- 图片素材库：私有上传、搜索、收藏、多选；可批量添加到画布或作为参考素材附加给 Agent。对话导入和生成结果先作为临时图片，用户显式保存后才进入个人素材库。
- 多 Agent 自主协作：Coordinator 拆分任务并委派 Planner、Canvas Editor、Reviewer；独立任务可并行，展示状态、失败重试和取消。右侧 Agent 对话是唯一聊天窗口；选中画布图片或文本框后，可把它加入该对话上下文。
- 画布底部提供紧凑图像生成栏和图像参数设置浮层；当前只实现前端交互，不调用真实图像生成服务。
- 用户配置 OpenAI 兼容模型，按 Agent 角色选择模型；密钥服务端加密保存。
- 高影响或收费操作需确认；普通可逆画布编辑按产品规则自动执行。
- 一台服务器 Docker Compose 部署 Web、API、Worker、PostgreSQL、Redis 和 MinIO；数据需异机备份。

## Agent 为什么属于这个产品

无限画布解决“把素材放到哪里”；Agent 解决“如何把创作目标变成一组可执行的画布操作”。例如用户选中三张商品图并说“排成一张简洁海报”，Agent 先规划版式，再提出移动、缩放和文字等操作，检查后交给用户预览。用户不必手动逐项操作，也不需要自己管理多个 Agent。

MVP 将流程拆为 Coordinator、Planner、Canvas Editor 和 Reviewer，是为了让分工、权限和结果可见：Coordinator 管任务顺序，Planner 负责方案，Canvas Editor 只能提出允许的画布操作，Reviewer 检查结果。API 验证用户权限和画布版本，用户接受后才写回，因此 Agent 能协助创作但不能绕过产品边界任意改数据。多 Agent 不是多人协作，也不是开放式地让模型彼此聊天。

## MVP 不包含

- 多人同时编辑同一画布、项目邀请/成员角色、在线光标与实时同步。
- 真实的外部生图和改图 API 调用；接口由用户后续提供，再按其文档规划接入。
- 管理员后台、组织工作区、订阅计费、公开模板/Agent 市场。
- 提示词库、视频/音频素材及创作工具、完整移动端编辑体验。
- 任意用户编写和执行代码、shell、SQL 或自定义插件。

## 核心流程

1. 注册并登录 → 创建个人项目和画布。
2. 上传或选择图片 → 多选添加到画布，或附加给 Agent 作为参考。
3. 配置 Agent 角色和模型 → 描述目标 → Coordinator 规划/委派 → 审阅结果 → 写回个人画布。
4. 自动保存画布；再次打开时恢复内容和上次视口。

## 已确定的产品边界

- MVP 采用单用户编辑；项目和素材为创建者私有，不做成员邀请或共享权限。
- 多 Agent 是产品核心，但使用受限的 Coordinator + 专业 Agent，不允许用户上传任意 Agent 代码。
- Agent 架构预留 Image Creator 工具适配层；当前不调用生图/改图 API，等待用户提供两类接口及文档。
- Agent 凭证归属于运行发起者；当前项目仅本人可访问，因此不涉及团队凭证共享。
- MinIO 继续用于单机部署的图片文件对象存储。
