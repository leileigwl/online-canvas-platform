# Spec Delta

## Purpose

定义用户如何配置并运行一组可自主分工的创作 Agent，使 Coordinator 能结合授权画布和素材拆解目标、委派专业任务、管理副作用并向用户呈现可审阅结果。

## ADDED Requirements

### Requirement: 用户自带模型接入
系统 MUST 允许用户配置 OpenAI 兼容模型连接，并按 Agent 角色选择模型配置；密钥必须隔离和加密保存。

#### Scenario: 用户测试并保存模型配置
- **WHEN** 用户提交 HTTPS 接口地址、API 密钥和模型名称并请求测试
- **THEN** 系统向该接口发起连通性测试，解释成功或失败，并仅在确认保存后供该用户的 Agent 使用

#### Scenario: 读取已保存配置
- **WHEN** 用户查看模型连接配置
- **THEN** 系统返回地址、模型名和已配置状态，不返回 API 密钥明文

#### Scenario: Agent 使用模型配置
- **WHEN** 用户运行 Coordinator 或专业 Agent
- **THEN** 系统只使用发起用户已配置且分配给对应角色的模型，不访问其他用户凭证

#### Scenario: 校验用户配置的 API 地址
- **WHEN** 用户保存或测试自定义 API 地址
- **THEN** 系统只允许 HTTPS 公网目标，并阻止访问本机、内网、链路本地和云元数据地址及重定向绕过

### Requirement: Coordinator 自主规划并委派专业 Agent
系统 MUST 允许 Coordinator 根据用户目标和授权上下文创建有依赖关系的任务图，并将任务委派给平台登记的专业 Agent。

#### Scenario: 多 Agent 拆解创作目标
- **WHEN** 用户提交需多个职责完成的创作目标
- **THEN** Coordinator 返回任务摘要、参与 Agent、任务依赖和预期结果，并持久化父运行及子任务关系

#### Scenario: 并行执行独立子任务
- **WHEN** 任务图中多个子任务互不依赖且未超过并行限制
- **THEN** 系统可并行派发这些子任务，并分别记录状态和输出

#### Scenario: 并行任务写入同一画布
- **WHEN** 多个子任务都需要修改同一画布
- **THEN** 系统按任务依赖或串行写入顺序提交变更，并在每次提交时检查最新 revision

#### Scenario: 依赖任务顺序执行
- **WHEN** 子任务依赖另一个任务的成功结果
- **THEN** 系统只在依赖完成后派发该子任务，依赖失败时停止或重新规划相关下游任务

#### Scenario: 用户请求超出平台能力
- **WHEN** 当前专业 Agent 或工具不能完成用户目标
- **THEN** Coordinator 说明限制并标记相应子任务失败或未支持，不伪造完成结果

### Requirement: Agent 依据授权上下文执行
系统 MUST 仅向 Agent 提供发起者拥有的项目、画布和明确选择的图片素材。

#### Scenario: Agent 读取个人画布
- **WHEN** 用户在自己的画布发起 Agent 运行
- **THEN** 系统使用该用户最新画布状态和 revision 构造上下文

#### Scenario: 用户附加多张参考图片
- **WHEN** 用户从可访问素材中选择一张或多张图片并附加到当前运行
- **THEN** Agent 仅将这些图片作为当前任务参考，发送前用户可移除附件

### Requirement: 工具调用必须受服务端约束
系统 MUST 仅执行平台登记且通过参数、权限、幂等和资源状态校验的工具。

#### Scenario: Agent 提交有效工具步骤
- **WHEN** 工具已登记、参数有效且发起者拥有目标资源
- **THEN** 系统按依赖关系执行该步骤并记录发起者、Agent、参数摘要和结果

#### Scenario: Agent 提交未知或越权调用
- **WHEN** 计划包含未登记工具、无效参数或未授权资源
- **THEN** 系统拒绝该步骤并记录可追踪的失败状态

#### Scenario: 画布版本变化后提交操作
- **WHEN** Agent 操作所依据的画布 revision 已被用户其他会话更新
- **THEN** 系统拒绝旧版本静默覆盖，并要求按最新文档重新校验或让用户选择恢复方案

### Requirement: 高影响工具调用需用户确认
系统 MUST 在执行费用型、破坏性或不可轻易撤销的工具前向用户展示影响并等待明确确认。

#### Scenario: 用户确认高影响操作
- **WHEN** 任务图包含当前已启用且可能产生费用的工具操作
- **THEN** 系统展示模型、操作目标、可获得的费用信息和副作用，且只在确认后执行

#### Scenario: 用户拒绝待确认步骤
- **WHEN** 用户拒绝需要确认的任务步骤
- **THEN** 系统不执行该步骤，并停止依赖该步骤的下游任务

### Requirement: Agent 运行状态可追踪和管理
系统 MUST 持久化 Coordinator 运行、子 Agent 任务、工具调用和可恢复状态，并允许用户查看、取消和重试。

#### Scenario: 用户刷新后查看运行
- **WHEN** Coordinator 或任一子任务仍在排队或执行
- **THEN** 系统恢复父运行、依赖、各子任务状态和最新进度

#### Scenario: 部分 Agent 任务失败
- **WHEN** 某些子任务成功而另一些失败
- **THEN** 系统分别展示成功产物与失败原因，允许重试失败任务且不重复已成功的副作用

#### Scenario: 用户取消运行
- **WHEN** 用户取消尚未完成的父运行
- **THEN** 系统阻止尚未开始的子任务、请求取消可取消任务并保留已完成结果与副作用记录

### Requirement: Agent 结果可审阅并安全写回画布
系统 MUST 在应用 Agent 生成的画布修改前展示可审阅操作摘要，并在所有者接受后写入个人画布。

#### Scenario: 用户审阅 Agent 画布操作
- **WHEN** Agent 生成新增、移动、修改或删除画布对象的结果
- **THEN** 系统展示操作摘要和受影响对象，等待 editor 明确接受或拒绝

#### Scenario: 用户接受 Agent 结果
- **WHEN** 用户接受一批画布变更且仍拥有目标画布
- **THEN** 系统将变更应用到当前个人文档并记录 Agent 来源
